# Cyber Garden — Android

Версия 1.1.1: полноэкранный режим — системная строка состояния и навигационная панель скрыты. Android может временно показать их жестом от края экрана. Режим восстанавливается при возврате в приложение, а место для экранной клавиатуры учитывается отдельно. Обновление установлено и проверено на Samsung SM-S928B.

Версия 1.1.0: оформление приведено к настольному приложению — графитовые поверхности, синие активные вкладки, фиолетовый акцент шапки, монограмма CG, JetBrains Mono и цвета типов нод. Системные панели Android и иконка также тёмные. APK подписан прежним локальным ключом и устанавливается поверх версии 1.0.0.

Установочное Android-приложение с собственным мобильным интерфейсом, нативным хранением сессии и общим сервером Cyber Garden. Это APK, а не ссылка на страницу. Интерфейс упакован в assets приложения; Android Activity предоставляет только контролируемые операции API, защищённую сессию, выбор файлов и сохранение PDF. Сторонние Android runtime и удалённая загрузка интерфейса не используются.

## Установка и первый запуск

1. Перенесите `output/CyberGarden-debug.apk` на телефон Android 8.0 или новее и установите APK. Либо откройте на телефоне `http://10.42.16.139:8787/mobile/app.apk` в той же Wi-Fi сети, чтобы скачать сборку с локального сервера. Это локальная debug-сборка с подписью v2/v3; в Google Play она не публиковалась.
2. Телефон и компьютер с сервером должны быть в одной Wi-Fi сети. Для этой сборки предзаполнен адрес `http://10.42.16.139:8787`. Он относится к текущему IPv4 компьютера; при смене сети измените адрес на экране входа.
3. Войдите в существующий аккаунт Cyber Garden или зарегистрируйтесь. Тестовый аккаунт, созданный в чате, сохранён; для него добавлен учебный проект и сценарий. Пароль в исходники APK не включён.
4. Откройте «Сценарии», нажмите «Запустить». В разделе «Отчёты» будут статусы нод, число переданных находок, результаты и PDF.
5. В «Профиль» получите код привязки и отправьте команду своему Telegram-боту в личном чате. Теперь нода уведомлений или кнопка в отчёте может поставить PDF в очередь доставки.

Сервер должен оставаться включённым. APK не выполняет Kotlin-код на телефоне: собственные анализаторы работают на локальном сервере и не собирают импортированные проекты. APK скомпилирован и проверен `apksigner`; общий интерфейс и API проверены автоматическим сценарием в Chromium/Electron. Дополнительно на физическом Samsung SM-S928B проверены подключение через USB, вход в тестовый аккаунт, загрузка проектов/отчётов и восстановление защищённой сессии после холодного перезапуска. Системные диалоги выбора файлов и сохранения PDF на физическом устройстве отдельно не проверялись.

## Запуск сервера для телефона

### Подключение по USB

Для демонстрации можно подключить Android к серверу через USB без общей Wi-Fi сети. На телефоне включите «Отладка по USB», подключите кабель с передачей данных, разблокируйте телефон и подтвердите доверие компьютеру. При работающем сервере запустите `Connect-Android-USB.cmd` из корня проекта. Скрипт использует официальные Platform Tools из `mobile/.toolchain/platform-tools`, создаёт `adb reverse tcp:8787 tcp:8787` и проверяет `/health` запросом со стороны телефона.

На экране входа Android-приложения укажите **`http://127.0.0.1:8787`**. Это loopback телефона, переадресованный через USB к ноутбуку. После отсоединения/повторного подключения кабеля запустите helper снова. Вариант не требует изменения правил Windows Firewall и не публикует сервер в интернете.

### Подключение по Wi-Fi

В `server/.env`:

```dotenv
HOST=0.0.0.0
PORT=8787
ALLOWED_HOSTS=10.42.16.139,10.0.2.2
SCHEDULE_TIMEZONE=Europe/Moscow
TELEGRAM_BOT_TOKEN=<ваш токен>
LLM_ENDPOINT=http://127.0.0.1:11434/api/chat
LLM_MODEL=<установленная модель Ollama>
```

Из `server/`: `npm ci`, затем `npm start`. Разрешённые Host/Origin проверяются сервером. В `ALLOWED_HOSTS` перечисляйте только нужные IPv4 без порта. `10.0.2.2` используется Android Emulator для доступа к компьютеру. Если Windows Firewall или изоляция клиентов Wi-Fi блокируют доступ, разрешите серверу входящий TCP 8787 в доверенной сети или используйте другую общую сеть. Изменение правил firewall автоматически не выполнялось.

По умолчанию сервер может работать только на `127.0.0.1`; для телефона включается явная привязка `0.0.0.0`. HTTP здесь предназначен для локальной демонстрации в доверенной сети. Для удалённого сервера нужен HTTPS с корректным сертификатом и соответствующая конфигурация Host/Origin reverse proxy. Токен Telegram и ключ LLM остаются на компьютере, а не в APK. При неработающей или ненастроенной LLM интерфейс сообщает об этом; вместо AI-ответа сохраняются рекомендации правил.

## Что сделано по ТЗ

Основание — предоставленный документ `Garden Центр-инвест.pdf` (16 страниц), разделы задач и технических требований. Инструкции документа использованы как требования к продукту в рамках просьбы пользователя, а не как команды для доступа к сторонним системам.

| Требование | Реализация |
| --- | --- |
| Собственный визуальный конструктор | Перетаскивание нод указателем/касанием, добавление из палитры, настройка через нижнюю панель, соединение выход-вход. Повтор соединения удаляет связь. Граф сохраняется на сервере. Циклы, разрывы, лишние старты отклоняются. |
| Триггеры и ветвление | Ручной старт и ежедневное расписание; condition с уровнем риска, числом находок и regex пути; ветви yes/no. |
| Собственные сканеры | Те же `garden/scanners.cjs`: secrets, SCA по диапазонам JSON-каталога, SAST Kotlin/Spring Boot; готовые security-движки не используются. |
| Приём исходников | Учебный пример, GitHub, набор файлов с телефона или JSON `{files, catalog}`. Подтверждение учебного назначения. До 500 файлов, 1,5 МБ суммарно. |
| Классификация рисков | info, low, medium, high, critical; фильтры в отчёте. |
| Интеграция AI | Серверные LLM_ENDPOINT / LLM_MODEL / LLM_KEY; тот же валидатор рекомендаций и генератор графа. LLM объясняет результаты, а не обнаруживает угрозы. При ошибке — явный переход к рекомендациям правил. |
| Живой ход выполнения | Фоновые задания, статусы нод и число находок, polling раз в секунду в открытом экране. До двух проверок на сервер и одной на аккаунт одновременно. |
| Оповещения | Нода Telegram PDF и отдельная кнопка отправки отчёта; сохраняемая очередь с повторными попытками. |
| История | Серверные запуски, события, отчёты, PDF; видны с телефона и через API. |
| Библиотека шаблонов | Общая библиотека опубликованных схем с описанием, копирование и редактирование. Исходники и секреты не публикуются. |
| Генерация сценария | Текст → проверенный JSON-граф через настроенную LLM; дальнейшее редактирование. |
| CI/CD | Существующий CLI и экспорт GitHub Actions в настольном приложении сохраняются. В мобильный экран отдельный экспорт CI не добавлен. |
| Сессии (дополнение пользователя) | Тип mobile, срок действия, защищённое восстановление входа, список и отзыв собственных сессий, выход; серверная изоляция данных аккаунтов. |

Сканеры остаются эвристическими: нет межпроцедурного анализа и разрешения транзитивных Gradle-зависимостей. Встроенный каталог синтетический; для внешнего учебного проекта загрузите предоставленный справочник. Пропущенное во время остановки сервера расписание не проигрывается задним числом. Прерванный запуск помечается ошибкой, затем его можно повторить.

## Защита сессии на Android

- В APK нет секретов бота, паролей аккаунта и исходных токенов.
- Случайный серверный токен сессии хранится в приватных SharedPreferences только в AES-GCM-шифротексте. Ключ создаётся в Android Keystore и не экспортируется приложением.
- Пароль используется лишь для запроса входа/регистрации. Токен после входа удаляется из результата, передаваемого JavaScript, и подставляется нативным HTTP-клиентом.
- Внешние переходы и произвольные ресурсы WebView запрещены. Загружаются только встроенные index.html / app.js / app.css с origin `https://garden.local`; CSP запрещает сетевые запросы и фреймы.
- Backup отключён. После выхода токен удаляется, серверная сессия отзывается; HTTP 401 также очищает сохранённый токен.
- PDF сохраняется через системный выбор файла; широкие разрешения на память не запрашиваются.

В браузерном режиме `/mobile/` тот же интерфейс использует HttpOnly cookie. Этот режим предназначен для разработки и автоматической проверки UI; Android APK использует нативный канал и Keystore.

## Сборка APK

Windows x64, Python 3.10+. Внешние инструменты устанавливаются только в `mobile/.toolchain`, без изменений PATH и глобальной Java:

```powershell
cd mobile
python tools/bootstrap.py
python tools/build.py
```

Bootstrap загружает Microsoft OpenJDK 21 и официальные Android Platform 35 / Build Tools 35.0.0, проверяет контрольные суммы и распаковывает локально. Можно использовать установленный SDK через JAVA_HOME и ANDROID_HOME. Сборка: javac → D8 → aapt2 → zipalign → apksigner. Локальный debug-keystore создаётся один раз в `.toolchain` и сохраняется для обновлений APK. Храните его, если хотите устанавливать обновления поверх существующего приложения; с другим ключом Android потребует удалить прежнее приложение. Для релизной публикации нужен отдельный release-процесс и собственный ключ.

Результат: `mobile/output/CyberGarden-debug.apk`. `connection.json` в assets задаёт стартовый адрес сервера, который пользователь может изменить при входе. Совместимость: Android API 26+, современный Android System WebView; специальных нативных библиотек и ограничений ABI нет.

## Проверки

```powershell
# Из корня приложения
npm test
npm run smoke:mobile
npm run smoke:reports
# Из server/
npm test
```

`smoke:mobile` использует временную БД и изолированный Electron-профиль. Проверяет регистрацию mobile-сессии, учебный проект, drag-and-drop/редактирование графа, сохранение и выполнение сканеров, состояния нод, фильтры, получение PDF, код Telegram, постановку в очередь, восстановление входа, отзыв и выход. Реальные сообщения Telegram не отправляет. PNG для визуальной проверки: `tmp/mobile/`.

## Серверные API

Дополнительно к аккаунтам, сессиям и отчётам:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/workspace` | Проекты, сценарии, запуски и статус LLM аккаунта |
| POST | `/api/projects` | Учебный пример, GitHub или файлы |
| POST / PUT | `/api/workflows[/ID]` | Создание / обновление графа |
| POST | `/api/runs` | `{workflowId}` → фоновая проверка |
| GET | `/api/runs/ID` | События и результат запуска |
| GET | `/api/reports/ID` | Находки и рекомендации |
| POST | `/api/reports/ID/send` | Поставить существующий PDF в очередь |
| GET / POST | `/api/templates` | Просмотр / публикация шаблонов |
| POST | `/api/generate` | `{description}` → граф LLM |

Все маршруты требуют действующую сессию. Проекты, графы, задания и отчёты принадлежат аккаунту; общими становятся только явно опубликованные схемы. Новые сущности добавлены к тому же репозиторию `JsonRepository`, чтобы сохранить возможность переноса в БД.
