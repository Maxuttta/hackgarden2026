# Cyber Garden

## Android-приложение

В `mobile/output/CyberGarden-debug.apk` собрана Android-версия: вход и сессии, проекты, визуальный редактор сценариев, запуск серверных анализаторов, ход выполнения, история, PDF и Telegram. [Установка, сборка и соответствие ТЗ](mobile/README.md). Сервер и настольное приложение используют ту же логику проверок; аккаунты и данные общие.

## Telegram и PDF-отчёты

Отчёт можно отправить прямо из приложения: нажмите **Telegram** в верхней панели, войдите в аккаунт сервера и при необходимости получите код привязки бота. Запустите проверку и нажмите **Отправить в Telegram** в отчёте. Кнопка доступна и для сохранённых отчётов в истории. Пароль не сохраняется; сессия хранится через Electron safeStorage и восстанавливается после перезапуска. Копировать JSON и токен webhook для ручной отправки не нужно. Сервер должен быть запущен; результат отправки подтверждает постановку в очередь, а не получение сообщения Telegram.

В `server/` добавлен отдельный локальный сервер: аккаунты и сессии, одноразовая привязка Telegram, PDF на русском, очередь доставки и файловое хранилище с отдельным адаптером для будущего переноса на БД. Запуск: `cd server`, `npm ci`, скопировать `.env.example` в `.env`, задать `TELEGRAM_BOT_TOKEN`, затем `npm start`. Откройте `http://127.0.0.1:8787`. Подробности и настройка webhook приложения — в [server/README.md](server/README.md).

Настольный конструктор проверок учебных Kotlin/Spring Boot проектов. Запуск из корня через `pnpm install --frozen-lockfile` и `pnpm start`. Windows-установщик собирается командой `pnpm dist` в `dist/garden`.

## Первый запуск

Стартовая схема готова к проверке встроенных синтетических файлов. Нажмите **Запустить**. Три находки показывают путь, строку, критичность и способ исправления. Последний блок отправляет JSON по HTTP на локальный приёмник. Полученный документ хранится в `last-webhook.json` в каталоге данных приложения. В настройках можно указать командный HTTPS webhook. Ключ API и адрес webhook сохраняются через Electron safeStorage.

Через **Открыть папку** выберите предоставленный учебный проект. Проверки читают Kotlin, Gradle Kotlin DSL, свойства, YAML и файлы ключей. Сборка и выполнение импортированных исходников не требуются. После перезапуска снова выберите папку и справочник. Схема и последние отчёты сохраняются.

## Сценарии

Добавьте блок из библиотеки нажатием или перетаскиванием. Потяните карточку для перемещения, нажмите для настройки. Сначала нажмите выход блока, затем вход следующего. Связь удаляется в настройках исходного блока. Блок условия сравнивает число находок заданной критичности с порогом и поддерживает регулярное выражение по пути. На пересечении активных ветвей результаты объединяются. Циклы и блоки без пути от старта отклоняются.

Для ежедневной проверки замените ручной старт блоком расписания, соедините его с анализатором и сохраните местное время. Расписание действует при открытом приложении. После повторного открытия проверьте источник и включите расписание сохранением времени.

Библиотека шаблонов позволяет публиковать схему с описанием в выбранную папку, в том числе общую сетевую, и брать независимую копию. Ключи и исходники в шаблон не входят. Импорт и экспорт отдельной схемы используют JSON.

## Анализаторы и справочник

Собственные построчные правила ищут литералы секретов, заголовки закрытых ключей, открытые правила Spring Security, отключение CSRF и конкатенацию данных в SQL. Проверьте контекст каждой находки. Эти эвристики не выполняют межпроцедурный анализ.

SCA сравнивает прямые координаты Gradle с числовыми версиями, включая переменные из Kotlin DSL и gradle.properties. Справочник подключается отдельным JSON. Нижняя граница включена, верхняя исключена. Встроенная запись синтетическая. Для оценки замените её справочником организаторов, приведённым к формату:

```json
[{"module":"garden.training:demo-codec","introduced":"1.0.0","fixed":"1.2.0","id":"TRAINING-001","severity":"high"}]
```

Критичность: info, low, medium, high, critical. Разрешение транзитивных зависимостей и вычисление произвольных выражений Gradle выходят за пределы текущей проверки.

## Модель

При первом обычном запуске приложение ищет установленную Qwen в локальной Ollama. Настройки позволяют выбрать другую модель, нативный endpoint Ollama (http://127.0.0.1:11434/api/chat) или совместимый chat/completions endpoint. Пустое имя включает только рекомендации правил.

В модель уходят сгруппированные названия проблем и рекомендации, без исходников и значений секретов. Ответ проверяется по идентификаторам групп, типам полей, длине текста и запрещённым ссылкам. Путь, строка и идентификатор из справочника берутся из результата анализатора. Журнал указывает модель либо причину перехода к правилам. Кнопка **Собрать с AI** предлагает схему по описанию, проверяет допустимые типы и показывает цепочку перед применением.

## CI и проверка

Кнопка **CI/CD** выдаёт GitHub Actions job для push и pull request. Поместите каталог garden, схему workflow.json и справочник advisories.json в учебный репозиторий. Настройте REPORT_WEBHOOK, если он используется. Код возврата CLI: 0 — проверка завершена, 1 — критические находки, 2 — ошибка сценария или интеграции.

```sh
node garden/cli.cjs ./training workflow.json advisories.json
pnpm test
pnpm smoke
```

CLI требует Node 22+. Smoke-тест запускает настоящий Electron в изолированном профиле, проверяет учебный отчёт, локальную HTTP-доставку и историю.


## Импорт из GitHub

Кнопка «Импорт проекта из GitHub» находится в левой панели под «Открыть сценарий».
Укажите URL корня репозитория, например `https://github.com/owner/repository`,
и при необходимости имя ветки или SHA коммита. Для приватных репозиториев нужен
токен GitHub с доступом на чтение содержимого выбранного репозитория. Токен не
сохраняется; авторизация браузера не используется.

Импорт загружает снимок поддерживаемых Kotlin-исходников и конфигураций, без
сборки или выполнения кода. Для получения изменений повторите импорт. Переход
к файлу в проводнике доступен только для проектов, открытых из локальной папки.
Действуют ограничения: 1500 файлов, 16 МБ суммарно, 2 МБ на файл и 120 секунд
на импорт. Ссылки и результаты сборки пропускаются. При превышении лимита
запросов GitHub укажите токен либо повторите импорт позже. Используйте только
проекты, разрешённые для учебной проверки.
